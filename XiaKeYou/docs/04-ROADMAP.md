- [ ] 建立 core / web 分離與固定模擬 tick。
- [ ] WorldGenerator：固定 seed、可重現地點與採集物。

**驗收**：在兩種瀏覽器重新開同一 seed，地圖與固定目標位置一致；玩家不會卡牆或走出可行走區域。

## M2 — 冒險閉環（第一個可玩切片）

- [ ] 1 個酒館／委託板及 2 個互動 NPC。
- [ ] 4 種動態任務模板，至少 12 個可重複生成的任務變體。
- [ ] 2 種敵人、近戰攻擊、受傷、死亡回城。
- [ ] 物品欄、採集、基本商店與任務交付。
- [ ] 任務追蹤提示、失敗及無法完成情況處理。
- [ ] 取得獎勵、回報任務、再次冒險的循環。

**驗收**：新玩家無需說明即可在城鎮接任務、前往荒野完成、回城領獎；四類任務各至少完成一次且不會產生不可達目標。

## M3 — 角色成長與存檔（MVP 封版條件）

- [ ] 三種行為式屬性成長、成長回饋。
- [ ] 遊戲時間、暫停、基本地區聲望。
- [ ] 以 IndexedDB 自動存檔及手動讀檔。
- [ ] 保存世界 seed、角色位置、背包、任務、時間與 NPC 關鍵狀態。
- [ ] 存檔 version、損壞處理、至少一版格式遷移測試。
- [ ] 音效／靜音設定、行動裝置基本操作與效能調整。
- [ ] 單元、E2E、鍵盤／觸控、存檔 round-trip 測試。

**驗收**：關閉頁面後重新開啟，存檔能恢復且不重複發獎；核心單人流程可在斷網狀態遊玩（初次載入及素材快取另行測試）。

- [ ] 內容與數值平衡：新手引導、敵人、報酬、戰鬥難度。

**驗收**：至少一輪外部試玩能完成閉環，重大存檔損壞與主流程卡住問題全數修正。

## M6 — 連線服務（P2，視需求啟動）

- [ ] 登入與帳號管理、雲端存檔、衝突解決。
- [ ] Render Node API、資料庫遷移與備份。
- [ ] API 錯誤重試、排隊、權限、速率限制、觀測。
- [ ] 多人合作的最小房間模型與權威伺服器技術驗證。
- [ ] 維運、資安、隱私、災難復原流程。

**啟動條件**：單人留存確定有價值，而且玩家確實需要跨裝置存檔或合作；否則不建立後端。

## 專案管理建議

- 每個 M1–M3 任務拆成獨立 PR；每個 PR 附重現步驟、功能截圖、測試結果。
- 一個子系統至少提供單元測試，遊戲閉環由 E2E 覆蓋。
- 以「玩家能完成什麼」作驗收，而非「已寫了多少程式碼」。
- 優先工作排序：**可玩閉環 > 存檔正確性 > 內容種類 > 複雜敘事 > 多人架構**。

## 預估風險排序

1. 隨機世界和任務可解性；透過 deterministic 測試覆蓋大量 seeds。
2. 存檔資料完整性；以 atomic save、版本化與 round-trip 測試降低風險。
3. 系統過度膨脹；每一階段都有嚴格不做項目。
4. IP 及第三方素材；原創優先，公開前審核授權。
5. Pages／Vercel 部署混亂；先選正式入口，再配置 CI/CD。
